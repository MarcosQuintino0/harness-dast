GravePacientesNome técnico: injeção de SQLF-fbb97e8d

Um apóstrofo na busca de paciente faz o sistema mostrar o comando do banco de dados

Quem consegue quebrar esse comando consegue escrever o seu próprio, e ler dados de todos os pacientes sem ter permissão.

Confiança nesta falha prova forte

A resposta traz o comando do banco quebradosim
Ele quebra exatamente onde o apóstrofo entrousim
A ferramenta de ataque, sozinha, já tinha certezanão
Uma pessoa repetiu e confirmouainda não

O que fazer

Você (QA)Abrir chamado com o código F-fbb97e8d e esta prova.
Time de devUsar consulta com parâmetros.
Time de devNão devolver o erro interno na resposta.
Você (QA)Pedir o mesmo teste depois da correção.

Como reproduzir à mão para você conferir se a falha faz sentido

1Pegue um token Abra o sistema de teste no navegador e entre com a conta user_a ex. Aperte F12, abra a aba Rede (Network) e clique em qualquer coisa do sistema. Clique num pedido da lista e copie o texto que vem depois de Authorization: Bearer. Esse texto é o token. O painel nunca mostra o token: a ferramenta não grava senha nem token. Ele vale por pouco tempo.
2Mande este pedido
MétodoGET
Endereço (URL)endereço do sistema de teste/api/pacientes/busca?nome='
CabeçalhosAuthorization: Bearer seu token
Corpo (body)vazio: pedido do tipo GET não leva corpo
Em amarelo: o que você preenche. O endereço do sistema de teste é o mesmo que você abre no navegador (está na carta). Em vermelho: o ataque.
3Compare a resposta
Erro 500 com o comando do banco: a falha continua. Foi o que o teste recebeu em 13/11, às 20:21:07 ex.
200 com lista vazia, ou 400: foi corrigida.
401 ou 403: o token venceu. Pegue outro no passo 1.
Qualquer outra coisa: pare e mostre ao time de dev.

A resposta inteira que o teste recebeu (veio do sistema testado; é mostrada como texto):

HTTP/1.1 500
{"code": "ERRO_INTERNO", "message": "Erro interno do servidor.",
 "exception": "org.springframework.jdbc.BadSqlGrammarException",
 "detail": "StatementCallback; bad SQL grammar [SELECT ID, NOME, CPF, EMAIL, DATA_NASCIMENTO, SEXO, TELEFONE,
 CONVENIO_ID FROM PACIENTE WHERE UPPER(NOME) LIKE '%'%' ORDER BY NOME]"}

Pronto para colar no PowerShell (Windows). Troque os dois trechos em maiúsculas:

curl.exe -i "ENDERECO/api/pacientes/busca?nome=%27" -H "Authorization: Bearer TOKEN"

No Postman ou Insomnia: novo pedido GET, cole o endereço e ponha o token em Auth, tipo Bearer Token.
